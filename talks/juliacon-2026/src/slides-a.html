All the quantum you need today

Three things, taken on faith. Every slide after this one is built from them.

1
Reversible computation. Ordinary computing, run without ever erasing. Assume it exists; the second half of this talk builds it from your Julia code.
2
One genuinely quantum gate: H. A coin flip you can undo: applied twice, you get your bit back. It puts a bit into two values at once, and your reversible code runs on both.
3
Measurement. Reading a bit collapses it to the value you read. That is the only way back out.

That's provably enough: reversible gates plus H are universal for quantum computation. (Shi 2002 · Aharonov 2003; hardware adds one phase gate, T, for efficiency. Nothing today needs it.)

A real introduction doesn't fit in 15 minutes, and I'm sorry for the speed run: quantum.country (Matuschak & Nielsen) is the one to read, free.

Why?

The mainstream stacks are a chimera: Python up front, a hardware description language underneath. The worst of both worlds.

Not just my opinion: "quantum circuits akin to assembly languages", "essentially ... circuit description languages" (POPL 2026) · OpenQASM is "similar to traditional Hardware Description Language (HDL) like Verilog and VHDL" (ACM Trans. Quantum Comput. 2021)

Neither half is how an algorithm designer thinks.

The dream

Separate the concerns, properly.

Classical code stays natural

Ordinary Julia: functions, loops, Base.sin.

And becoming a quantum subroutine must require no rewriting. Not a port, not an annotation, not a gate-by-gate translation.

Quantum code obeys the axioms

Only what the operational rules of quantum mechanics allow: prepare, transform, measure.

Nothing is copied. Nothing is discarded silently. Measurement consumes. The language enforces this, not a linter.

The rest of this talk is these two promises, kept: the first half makes quantum code lawful, the second half makes classical code free.

a program: values, operators, scope

Sturm.jl is a handful of design decisions about how quantum programs should read. The first part of this talk walks through them, one at a time, each with the Julia feature that made it work.

Quantum data is a value, not a wire

x = QInt{4}(3)     # a 4-bit quantum integer
add!(x, 2)         # |3⟩ → |5⟩, in place
superpose!(x)      # all sixteen values at once
s = x + 2          # ordinary arithmetic; a fresh register comes back

The width lives in the type, so every operation is specialized at compile time. Comparisons work too: x < y just returns a quantum bool, because that's what it is.

Why Julia: user-defined types are first-class citizens. A quantum integer can behave like a number without pretending to be one.

Crossing the classical/quantum boundary is a type conversion

q = QBool(0.7)     # classical → quantum: prepare
b = Bool(q)        # quantum → classical: measure

Measurement consumes. Use q after this and you get an error, not a silently wrong answer.

And the round trip is a law with a test: Bool(QBool(b)) == b, for both values of b, every CI run.

Why Julia: constructors already are the conversion idiom. The most consequential operation in quantum mechanics needed no new syntax.

Scope is physical

eager(4) do ctx
    q = QBool(0.5)      # a local qubit
    r = false ⊻ q       # quantum scratch
    Bool(q)             # this value leaves the block
end                     # ← r is discarded exactly here

Discarding a qubit is a physical operation: the environment keeps its half of any correlation. So it has to happen at a definite moment, not whenever a garbage collector gets around to it.

Why Julia: a do-block is a genuine try/finally. Scope exit is deterministic, so we could afford to make it mean something.

Control flow can be quantum

when(c) do          # `if`, but c is a qubit
    add!(x, 3)      # happens in the branch where c is 1
end                 # both branches carry on, in superposition

Inside the block the rules tighten: measuring in there is physically meaningless, so trying it raises an error at the exact call, with a message that says why.

Why Julia: do-block syntax lets a brand-new control construct read as if it had always been in the language. when is a plain function taking a closure, not a macro.

What physics forbids, dispatch forbids

julia> ctrl(Protect(enc))
ERROR: MethodError: no method matching ctrl(::Protect{…})

There is a theorem that you cannot take an error-corrected process and condition it on a qubit. In most systems that lives in the documentation. Here it's a method that doesn't exist.

Why Julia: we didn't write a checker or a linter. We just didn't write the method, and the error message points at the exact call.

“Given an oracle for f …”

Of  |x⟩|y⟩ = |x⟩|y ⊕ f(x)⟩

In words: a machine that takes x and y and returns x and y ⊻ f(x). Your function, installed as a gate.

Grover · Shor · Deutsch–Jozsa · phase estimation: every one of them starts from this sentence. The papers never say where the oracle comes from.

your ordinary f  →  Bennett.jl  →  reversible gates  →  controlled  →  oracle(f, x)
